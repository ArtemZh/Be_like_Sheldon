# Куди доїду за день — передача проєкту

Стан на 2026-08-30. Гілка `feat/daytrip-isochrones`, 36 комітів, не запушено.

## Що це

Карта Німеччини, яка відповідає на питання «куди можна з'їздити потягом
туди-назад за один день». Клікаєш будь-де на карті — беремо найближчу
станцію й показуємо, куди звідти можна доїхати, встигнувши повернутись.

Ключове рішення, з якого виріс увесь проєкт: метрика — не час у дорозі, а
**корисний час на місці**. Вікно між приїздом і останнім потягом назад,
мінус година на вокзал, каву й хотдог. Гамбург за дві години в дорозі
марний, якщо назад є лише один вечірній потяг.

## Як воно працює

Передрахунку відповідей немає. Збірка перетворює GTFS на компактний
бінарний розклад, браузер вантажить його один раз і рахує RAPTOR у Web
Worker — 10–40 мс на запит. Тому стартом може бути будь-яка з 7737
станцій, а не одна з наперед обраних.

```
GTFS zip
  │  build/  — Python: ingest, вибір сервісних днів, бінарний експорт
  ▼
web/public/data/  feed.bin (9.2 МБ, 3.8 у gzip) + stations.json + network.json
  ▼
web/src/worker.js — RAPTOR + зони у фоновому потоці
  ▼
web/src/map.js — MapLibre: крапки, зони, шкала часу
```

### Python (`build/`)

| Модуль | Відповідальність |
|---|---|
| `gtfs_ingest.py` | GTFS → `Feed`; фільтр на потяги, зведення платформ до станцій |
| `calendar_pick.py` | які service_id їздять у понеділок і наступного дня |
| `feed.py` | компактне представлення розкладу, `reversed()` |
| `raptor.py` | RAPTOR: найраніші приїзди від станції |
| `daytrip.py` | злиття прямого й зворотного профілів у вікно |
| `binary_feed.py` | `Feed` → `feed.bin` + `feed.meta.json` |
| `network.py` | схема мережі з патернів |
| `origins.py` | 15 головних вокзалів для позначок на карті |
| `cli.py` | збірка цілком |

### Фронтенд (`web/src/`)

`raptor.js` і `daytrip.js` — порт пітонівських модулів на типізовані
масиви. `feed.js` читає бінарний фід. `grid.js` будує зони. `metrics.js`,
`timeline.js`, `i18n.js` — чиста логіка з тестами. `map.js` — єдине місце
з DOM і MapLibre. `worker.js` — усе важке.

## Запуск

```bash
# дані (потрібен gtfs/db.zip, див. README)
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/python -m build.cli gtfs/db.zip --out web/public/data

# фронтенд
cd web && npm install && npm run dev
```

## Перевірка

```bash
.venv/bin/pytest              # 49 тестів на фікстурному фіді
.venv/bin/pytest -m slow      # 2 тести на справжньому, потребує gtfs/db.zip
cd web && npm test            # 49 тестів фронтенду
node tools/crosscheck.mjs     # звірка JS проти Python на справжньому фіді
```

**`crosscheck.mjs` — головний запобіжник.** Порт RAPTOR легко зробити
«майже правильним»: фікстурні тести проходять, а на країні результати
розходяться. Скрипт ганяє обидві реалізації на тому самому фіді й вимагає
нульової розбіжності. Якщо чіпаєте роутинг — запускайте його.

## Рішення, які варто знати перед правками

**Платформи зведені до станцій.** У DELFI-фіді кожна платформа — окрема
зупинка зі спільним `parent_station`: 16566 рядків на 7737 станцій. Без
зведення карта показувала б по сім кружечків на один Берлін. Назва
станції — найчастіша серед платформ, бо батьківський рядок Берліна
називається «S+U Berlin Hauptbahnhof», а в Гамбурга його немає взагалі.

**Пересадка коштує 5 хвилин** штрафу на посадку в RAPTOR. Це наслідок
зведення: коли платформи стали одним вузлом, перехід між ними перестав
коштувати часу сам собою.

**Раунди RAPTOR читають лише попередній раунд.** Була помилка: обидві
реалізації оновлювали спільний масив часів під час раунду, і відповідь
залежала від порядку обходу патернів. Через це Python і JS розходились, а
результати були завищені — змішування раундів фактично дозволяло
необмежену кількість пересадок. Не «оптимізуйте» це назад.

**Два сервісні дні.** Режим «доба» вимагає вівторкових ранкових потягів,
а вони належать вівторковому `service_id`. Рейс, чий сервіс їздить обидва
дні, входить у розклад двічі — це різні потяги, не дублювання.

**Зони будує воркер.** Перебудова коштує до 280 мс і в кадр не влазить ні
за яких налаштувань сітки. Спроби вкластися грубішою сіткою давали 40, а
потім 24 кадри — будь-яка перебудова блокує головний потік. Не повертайте
її туди.

**Радіус пішохідної зони росте з корисним часом**: за 4 вільні години це
10 км в один бік. Стеля 16 км, бо 8 годин дали б похід, та й сітку роздуває
квадратично.

**Ділянки мережі, довші за 100 км, відкидаються** — це не перегони, а
експреси, що пропускають станції. 41 ділянка з 9346, але кожна тягнулась
через пів карти.

## Дані

Фід — gtfs.de (агрегує національний DELFI), ліцензія CC-BY 4.0.
Зараз зібрано з `rv_free` — **тільки регіональні потяги, без ICE**. Тому
далекі напрямки бідніші, ніж мали б бути, а список головних вокзалів
містить Neuss і Hanau замість Штутгарта й Лейпцига. Повний фід (272 МБ)
це виправить без змін у коді.

Безкоштовні фіди покривають найближчі тижні, тож дані треба перезбирати.

`web/public/data/` у git не входить — генерується збіркою.

## Відоме незроблене

- **GitHub Pages задеплоїть сайт без даних**: `web/public/data/` у
  `.gitignore`, а CI не має фіду. Треба або комітити дані, або качати фід
  у workflow.
- **Базова карта — CARTO Positron із CDN**. Обговорювали заміну на власну
  геометрію з Natural Earth (тільки міста й ріки), рішення не ухвалено.
- **`web/public/intro.webp`** — кадр із серіалу, ліцензія репозиторію на
  нього не поширюється. Має значення при публікації.
- Спека `docs/superpowers/specs/` описує архітектуру, якої вже немає
  (статичний передрахунок); у ній є врізка про це. План
  `docs/superpowers/plans/` виконано, але теж застарів у частині зон і
  роутингу.

## Що можна зробити далі

Повний фід з ICE — найдешевша зміна з найбільшим ефектом. Далі: довільний
час виїзду замість зашитих 09:00 (воркер уже приймає це параметром),
транзитивна редукція мережі замість порогу 100 км, власна базова карта.
